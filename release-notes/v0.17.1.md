A bug-fix release. One of these stops ALBIS opening files it can read
perfectly well, so upgrade if you work with HDF5.

### Fixed

- **HDF5 files that were locked, not broken.** ALBIS refused them with *"not
  a readable HDF5 file (it may be incomplete or corrupt)"* when all that had
  happened was that it could not take the file lock — another process holding
  the file, or a filesystem that cannot lock, which is routine on the network
  mounts beamlines serve data from. Not one byte had been read, so there was
  never any evidence about the file. It now opens such a file anyway as a last
  resort, and when it genuinely cannot, it says *locked*, and says the file is
  not damaged.
- **A truncated HDF5 file no longer returns a server error.** It escaped as an
  unhandled 500 instead of the "cannot read this file" it was supposed to give.
- **Two tooltips at once** on the folder-browse button and its neighbours. Ours
  was taking the browser's away a beat too late to stop it appearing.
- **ROI profile axes stop at zero.** A profile of photon counts was labelled
  down to −1.9, which reads as the baseline going negative. It cannot.
- A box ROI's reserved region fell one pixel short of the rectangle drawn.

### Changed

- **Peak markers thin out as they multiply.** At the default 100 peaks they
  were covering the diffraction they annotate. Their *size* is unchanged — that
  tracks the spot's footprint — only the stroke weight gives, and exports keep
  full weight.
- **Resolution-ring labels keep off the ROI**, without ever vanishing to do it.
- **About** now names the licence (MIT), the DOI to cite, and the author's
  affiliation — and admits ALBIS reads MYTHEN files, which it always has.
