A bugfix release for file and folder names with special characters, thanks to Benjamin Luethi for reporting that `a¦b.tiff` would not open.

### Fixed

- **On Windows, files and folders with umlauts or other special characters
  open from the system's file dialog.** Picking `a¦b.tiff`, or any file in a
  folder such as `Jürg`, opened ALBIS's own file browser instead of the
  image, because the chosen path reached ALBIS garbled.
- **On Linux, a file named in a foreign encoding no longer empties the file
  browser.** A name copied from Windows, out of an old archive or from a share
  with another character set made the whole folder listing fail. Such a file
  is now left out, the rest of the folder is listed, and the log names it so
  it can be renamed.
- **HDF5 datasets with Greek, Japanese or other non-Latin names save as
  CSV,** instead of failing with a server error.
- **The log file is written as UTF-8 on Windows too,** so **View Log** shows
  umlauts and accented letters, and entries naming files in other scripts
  are no longer lost.

---

Update if you work on Windows with paths that are not plain ASCII, or on
Linux with data copied from elsewhere. Nothing has moved.
