**Check for Updates** used to tell you a newer ALBIS existed, then hand you a
release page with nine files on it, none of them labelled *yours*.

### Added

- **It knows how you installed ALBIS** — AppImage, Windows installer, portable
  zip, macOS disk image, container, checkout — and names the one file for your
  machine, or the one command to run, with a copy button.
- **It fetches that file and checks it.** The download is hashed as it arrives
  and compared against the release's own `SHA256SUMS.txt`. No match, no file.
- **It can install it, if you turn that on.** `ui.allow_update_apply` is off by
  default. On Linux and Windows it adds **Install Update** — never on an
  unverified download, never while a live watch or export is running. ALBIS
  closes when it is done; you start it again.

### Changed

- **Every CSV export is one table**, with the provenance in a leading comment
  block, so `pandas.read_csv(path, comment="#")` just works.

### Fixed

- **A release candidate would have been announced to everyone.** GitHub does
  not infer "pre-release" from a semver tag, so `v1.0.0-rc1` would have become
  the *latest* release. Caught before it could happen.

### Security

- Two CodeQL findings closed: the handoff manifest path, and a log line an
  HDF5 group name could forge.

---

Nothing is downloaded or installed unless you click. The update check is still
one request per start, still switchable off. **Still heading for 1.0.0-rc1** —
which will now no longer ambush anyone.
