**Shine Bright Like a Diamond.** A release for Diamond Light Source: ALBIS now
knows the PILATUS 12M at beamline I23, and the Linux build runs on the RHEL 8
workstations Diamond's beamlines use.

### Added

- **I23's PILATUS 12M draws its resolution rings with no geometry file.** The
  detector's 24 module rows sit on a half cylinder around the sample, which a
  file header cannot describe, so until now the rings needed a DIALS
  `imported.expt` loaded by hand. ALBIS now recognises the detector by its
  serial number (S/N 120-0100) in CBF files and DECTRIS TIFFs and uses its
  fixed geometry, the same one DIALS uses. The rings panel says
  *Auto geometry: DLS I23 PILATUS 12M 120-0100*. A geometry file you load
  yourself still takes precedence. No other detector is affected.

### Changed

- **The Linux AppImage and tarball run on RHEL, Rocky and AlmaLinux 8 and 9.**
  They needed glibc 2.35 before; they now need 2.28. Ubuntu 22.04 and later
  lose nothing. Every release is now started on Rocky Linux 8, Ubuntu 22.04
  and Ubuntu 24.04 before it is published. On a managed workstation without
  FUSE, use the tarball: it needs nothing installed and can be unpacked once
  to shared software storage for all users.

### Fixed

- **I23 rings no longer collapse onto the beam centre.** The I23 header's
  `Detector_distance` (0.010 m) is an offset from the detector's fixed
  position, not the distance to the sample. ALBIS took it as the distance, so
  even with a geometry file the rings were drawn as if the detector were 10 mm
  away. The distance field now shows the real one, about 260 mm, and the
  rings agree with DIALS to within 0.2%. Exported files keep the header's own
  value, because DIALS reads that too.

---

Nothing changes for other detectors or file formats. If you are not at I23 and
not on RHEL 8 or 9, **Help → Check for Updates** will offer this whenever it
suits you.
