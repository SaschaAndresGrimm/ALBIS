# ALBIS 0.10.3: Strixel Things

For most of its life ALBIS assumed a pixel is a pixel — a tidy little square. DECTRIS **POLLUX PANORAMA HR** disagrees: its pixels are **strixels**, elongated rectangles (37.5 × 150 µm on the unit we tested — four times taller than wide). Feed one of those to a square-pixel viewer and your diffraction comes out squashed, your rings turn into eggs, and your radial profile quietly lies. 0.10.3 fixes all of that. The data matrix is still pixelwise; we just taught every coordinate transform that up and across aren't the same distance anymore.

## Highlights

- **Pixels with the right shape.** Master-file `x_pixel_size` and `y_pixel_size` are kept distinct (no more averaging them into one number), and the image is displayed with its true physical aspect ratio. A POLLUX frame finally looks like the detector, not like someone sat on it.
- **Everything stays glued down.** The per-axis aspect is threaded through the whole stack — cursor readout, box/line/circle ROIs, peak markers, resolution rings, the overview thumbnail, multi-window sync, and image export. Hover a pixel, drag an ROI, drop a peak marker: they all land exactly where they should.
- **Round rings, round ROIs.** Because the stretched display is physically isotropic, resolution rings stay true circles — and a circular/annulus ROI is now a real **resolution shell**: a circle on screen (an ellipse in pixel space) that lines up with the rings instead of fighting them.
- **Honest radial profiles.** Azimuthal integration now bins by *physical* radius, so pixels at the same resolution land in the same bin no matter the direction, and the profile x-axis reads in millimetres. No more smearing just because the pixels are tall.
- **Numbers in real units.** The ROI panel now reports size in **mm** and area in **mm²** right next to the pixel counts — true for strixels and squares alike.

## Under The Hood

- One idea carries the whole feature: `pixelAspect = y_pixel_size / x_pixel_size`, with X as the reference axis and Y stretched by the aspect. For square detectors `pixelAspect === 1`, so every code path is byte-for-byte identical to 0.10.2 — zero regression risk for EIGER/PILATUS/SELUN users.
- Circular ROI radii are stored in X-pixel-equivalent units, which map to a true screen circle and convert to physical mm by a single multiply.
- ROI statistics still count each data pixel equally — on a uniform strixel detector every pixel has the same area, so weighting would change nothing (and would be wrong for photon-counting sums).
- New backend fields `pixel_size_x_um` / `pixel_size_y_um` on `/api/analysis/params`; `pixel_size_um` is retained as the reference (X) size for compatibility. New i18n strings localized across all 13 locales.

## Compatibility

- Added **DECTRIS JUNGFRAU** and **POLLUX** (rectangular strixel pixels) to the supported-detector list.
