# ALBIS 0.14.0: The Metadata Was There All Along, Just Not Where Anyone Looks

Every TIFF ALBIS has ever exported carried its DECTRIS metadata in the wrong
place. Not missing — *misplaced*, by a rule that only ALBIS followed. Open one
in ALBIS and everything read back perfectly. Open it in anything else and the
exposure time came out as `2.78e-309`.

## Highlights

- **Exported TIFFs are readable by other software.** The DECTRIS tag stated its value offsets relative to itself; the format says they are relative to the file, the same way EXIF works. Writer and reader agreed with each other and with nobody else, so the series id, timestamp, exposure time, energy, wavelength, beam centre and detector distance all decoded to whatever bytes happened to sit at that offset. Only the four values small enough to be stored inline ever survived the trip.
- **Files you already exported still open.** ALBIS recognises both layouts and picks the right one, so nothing in your existing data goes dark. Their metadata stays wrong for *other* tools, though — re-export anything you plan to hand to XDS, DIALS, or a colleague.
- **tifffile 2026.8.16**, which is what caught this. It decodes the DECTRIS tag itself and was the first reader to look at our output without sharing our assumption.

## Why This Matters

A test suite that only ever reads files with the same code that wrote them will
agree with itself forever. That is exactly what happened here — the round-trip
test passed every single time, for the whole life of the bug, because both ends
were wrong in the same direction. The new tests parse the file from the TIFF
spec instead, which is the only kind of reader that could ever have failed.

It also lands at the last moment it could land cheaply. `docs/COMPATIBILITY.md`
lists exported file layouts as a covered surface, so once `1.0` binds, changing
these bytes would take a major release. That is also why this is `0.14.0` and
not `0.13.1`: the policy says a patch changes nothing in a covered surface, and
the first release to invoke those rules should be one that obeys them.

747 Python tests, 447 JavaScript.
