# ALBIS 0.11.0: Reading the Manual

This one is mostly about ALBIS being honest with you. It stops pretending a file it cannot read is its own fault, stops promising restarts it does not need, and finally admits in writing that it has supported MYTHEN all along. Along the way a handful of bugs turned up that had been quietly showing you the wrong thing.

## Highlights

- **Big-endian data loads again.** Any frame stored most-significant-byte-first — an HDF5 stack written that way, or every JUNGFRAUJOCH preview image, whose format is big-endian by definition — failed with a server error rather than appearing. The byte swap they all pass through used a NumPy call that NumPy 2.0 removed, so it broke for exactly the data that needed it and nothing else.
- **A mask can no longer end up on the wrong file.** Switch files while the pixel mask is still loading and the old file's mask used to land on the new one. Masks from the same detector are the same shape, so nothing looked wrong — the frame rendered, the statistics computed, and both were quietly measuring against another dataset's mask. It did not even correct itself.
- **Stepping through frames got roughly twice as fast on large detectors.** Whole-image statistics ran on every arrow-key press and found the median by copying every pixel into a fresh array. On a 4M detector that was 150 ms and 114 MB of rubbish per frame; on a 16M, 560 ms and 431 MB. Same numbers out, a third of the work.
- **Files that cannot be read say so.** A truncated or corrupt HDF5, TIFF, CBF or EDF — usually one the filewriter has not finished — used to surface as "Internal Server Error". It now names the file and the reason. A short EDF is the sly one: fabio silently zero-fills the part it could not read, so half a frame was being displayed as real zero counts.
- **Settings is a dialog again, not a wall.** Twenty-three controls on one scrolling page are now four tabs. **Allowed hosts**, **Response compression** and **Health check timeout** finally have fields — before this, the one deployment the docs walk you through required hand-editing JSON. And instead of stamping "RESTART" on ten controls, it tells you what you actually changed: *Restart to apply: Port, Response compression*.
- **There is a User Guide.** [docs/USER_GUIDE.md](https://github.com/SaschaAndresGrimm/ALBIS/blob/main/docs/USER_GUIDE.md), organised by what you are trying to do. Until now the documentation went from "here is the installer" straight to "here is the REST API", with the actual work left as an exercise.

## Also in this release

- **MYTHEN(2) is documented.** It has worked for ages. Nobody could have known.
- **The built-in help lists the keyboard shortcuts.** ALBIS advertises twelve in its own menus and the help described two, so the command palette (`⌘K`) was a secret.
- **ALBIS no longer answers requests a web page made on your behalf.** A page whose own domain resolves to `127.0.0.1` was, to the browser, same-origin with ALBIS — and `POST /api/upload` uses a form encoding older than CORS, so any page could drop a file in your data directory and just not read the reply. Both are now refused. Nothing changes for local use or for scripts pushing frames. **If you run behind a reverse proxy, add its hostname to Settings → Connection → Allowed hosts.**
- **A configuration file ALBIS cannot read no longer stops it starting.** Config is loaded before logging exists, so a truncated file — or one written by a newer ALBIS — ended the process with nothing to show for it. From a double-clicked app that looked like nothing happening at all. It now starts on defaults and says so. Saving settings is also atomic, so an interrupted save cannot cause the problem in the first place.
- **Metadata from a live producer can no longer break the frame it describes.** A sample name with a non-Latin character, a line break, or simply a very long one would take the response down until a clean frame replaced it.
- **The release build now opens an image before calling itself a release.** It checked that the process started and served the UI, so a build that had lost its image decoders passed every gate and failed on your first file.
- Docker images no longer allow absolute paths — they listen on `0.0.0.0` with no authentication, where the desktop default is the wrong one.
- Dependency bumps: uvicorn 0.52.3, zstandard 0.25.0, pyobjc 12.2.2.

## Upgrade note

One change can need action: if you reach ALBIS through a **reverse proxy**, add the proxy's hostname to **Settings → Connection → Allowed hosts**, or every request answers `403`. Direct local use, LAN access and Docker are unaffected.
