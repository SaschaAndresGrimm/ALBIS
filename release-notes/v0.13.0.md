# ALBIS 0.13.0: Now Reads Files That Are Still Being Written

Turns out the viewer built for live detector data could not open a file the
detector was currently writing. It answered *"may be incomplete or corrupt"* —
about a perfectly good file. That's fixed, along with four other things that
were quietly wrong and one feature you've probably wanted since day one.

## Highlights

- **Live series, actually live.** Open a stack mid-run: ALBIS reads it, and the frame slider grows as frames arrive. Stops asking when the filewriter closes the file. Your current frame, playback and mask stay put.
- **JUNGFRAUJOCH preview worked exactly never.** Every message failed to decode against the pinned `cbor2`, the error went into the log, and the preview showed nothing. Now it shows something.
- **Big folders stop being a trap.** Directory scans have budgets and say when a listing is partial, instead of holding a worker for minutes and handing you an incomplete list with a straight face.
- **File → Open Recent.** Ten files, newest first. Yes, finally.
- **Exported files admit who made them.** A converted CBF no longer poses as raw detector output: it names the ALBIS build, the source frame, and the pixel substitutions applied.
- **`docker run -e ALBIS_DATA_ROOT=/data`** does what you'd expect. So do `--port`, `--data-root` and friends.
- **Python 3.13**, three years ahead of the interpreter that expires this October. Nothing to install — it's inside the bundle.

## Also

DNS-rebinding protection now applies to the LAN bind where the attack actually
lives; the Docker image ships the dependency set it claims to; `NaN` in a
detector field no longer breaks the geometry panel; and
[docs/COMPATIBILITY.md](../docs/COMPATIBILITY.md) says what 1.0 will promise.

## Why This Matters

This is the release where the beamline workflows stop being "works on a
workstation". Everything above was found by writing the tests that should have
existed — 741 of them now, up from 340.
