# ALBIS 0.10.9: Bytes on a Diet

ALBIS can run on a server with the browser somewhere else — and it felt like it. The cause turned out to be embarrassingly simple: nothing sent to the browser was compressed or cacheable. A single EIGER 4M frame crossed the wire as ~18 MB of raw pixels, and the frontend re-downloaded all ninety of its modules on every reload, forever. This release is about that.

## Highlights

- **Frames travel compressed now.** zstd where your browser supports it, gzip where it does not. A real EIGER 1M frame drops from 4.4 MB to 1.9 MB — 57% fewer bytes, and *faster* to produce than the gzip it replaces. Local use pays nothing: a browser on the same machine is never compressed, because that transfer was already instant.
- **The UI stops re-downloading itself.** A cold load falls from 1134 KB to 323 KB, and an unchanged reload now transfers no page bodies at all — just a flurry of `304`s.
- **Frames you have already seen are free.** Step back a frame, or replay a stretch you just watched, and it appears instantly with no request. The budget is memory rather than a frame count (a frame is ~4 MB on a 1M detector and ~18 MB on a 4M), so tune it in **Settings → Viewer**.
- **Playback no longer freezes at higher frame rates.** If a frame took longer to load than the gap between ticks, every tick killed the load the previous one had started, so nothing appeared until you pressed stop — and the faster you set it, the more certain the stall. Playback now waits for the frame in flight instead of cancelling it, and the chosen rate acts as a ceiling rather than a promise.

## Also in this release

- The Settings dialog no longer discards configuration it has no field for. It was quietly resetting hand-edited keys on save.
- JUNGFRAUJOCH preview: a **Test** button, a new `GET /api/jfjoch/probe`, and an endpoint field that accepts a bare `host:port`.
- The SIMPLON address field remembers addresses that actually answered, and adopts a working API version when the configured one is absent.
- `GET /api/health` now reports which compression codecs the running build can produce — useful when a packaged build is quietly missing one.
- New dependency: `zstandard` (BSD-3-Clause). Optional at runtime; without it ALBIS serves gzip instead of failing.
