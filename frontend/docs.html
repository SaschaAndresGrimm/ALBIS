ALBIS

ALBULA-style viewer for DECTRIS detector data

ALBIS is a free, open-source viewer for DECTRIS detector data, in the style of ALBULA. It opens HDF5 stacks, TIFF, CBF, EDF and MYTHEN acquisitions, follows a running experiment live, and runs on your own computer or on the machine that holds the data, viewed from a browser elsewhere.

Resolution rings follow the true detector geometry, zoomed-in pixels show their values, ROI tools measure regions, series can be summed or averaged, and figures export sharp for slides and papers.

New here? Start with File → Open, then use the tabs on the right: View for contrast and zoom, Data for source, dataset and metadata, Overlay for ROI, rings and peaks.

Quick start

  • Open data: File → Open to load HDF5, TIFF, CBF(.gz) or EDF files, or a MYTHEN acquisition by picking its .cfg file.
  • Reopen data: File → Open Recent lists the last ten files you opened, newest first. Watched folders and live streams are not listed.
  • Open from the file manager: double-click an .h5, .hdf5, .cbf, .edf, .tif or .tiff file. On Windows, pick ALBIS once under Open with to make it the default; on macOS use Get Info → Open with. If ALBIS is already running, the file opens there instead of starting a second copy.
  • Navigate frames with the slider, the index field, play/pause, and the arrow keys.
  • Use the Data tab to select the data source, dataset and threshold, and to inspect file metadata.
  • Use the Overlay tab for ROI statistics, resolution rings and the peak finder.
  • Export what you see: File → Convert Dataset… writes TIFF or CBF, File → Export Animation… writes an animated GIF.
  • Settings → Preferences… opens the Settings dialog, grouped into Viewer, Connection, Data and Logging. Fields that only take effect on the next start say so as you change them.

Interaction

  • Mouse wheel zoom at the cursor.
  • Left-drag pan the image (also while zoomed out).
  • Shift + Left-drag contrast and brightness: horizontal is contrast, vertical is brightness.
  • Right-drag draw an ROI (when ROI mode is on).
  • Double-click quick zoom in.
  • F full screen.
  • F1 this page.

Keyboard shortcuts

Shown with the macOS modifier. On Windows and Linux use Ctrl where ⌘ appears and Alt where ⌥ appears.

  • ⌘K Command Palette — the fastest way to reach anything below.
  • ⌘O Open…
  • ⌘W Close File
  • ⌘N ⇧⌘N New Window, Duplicate Window

  • ⌘S save the full image

Data sources

  • File: load local files from disk.
  • MYTHEN acquisition: a folder holding one .cfg descriptor and one FrameNNNN.dat per exposure. Open the .cfg and the whole acquisition is assembled into a single image — channel across, frame down, counts as intensity.
  • Watch Folder: poll folders for new files.
  • SIMPLON Monitor: live images from a detector. Enter its hostname or IP address (for example 192.168.1.10); http:// and the default port 80 are filled in. Press Test (or Enter in the address field) to check the connection — it names the detector on success, or the reason on failure (unknown host, refused port, wrong API version).
  • JUNGFRAUJOCH Preview: subscribe to the ZeroMQ preview CBOR stream, with reflection overlays. Enter host:port and tcp:// is filled in; there is no default preview port, so the port is required. Test checks that the port accepts connections — frames are confirmed once the preview starts.
  • Remote Stream: frames pushed to ALBIS through its API, by source id. For this API and every configuration key, see the Power User Guide (in Project links).

Test a detector (beta)

The Detector tab is a quick way to check a DECTRIS detector: connect over SIMPLON, take a test series and watch it live, without writing code. It is off by default; switch it on under Settings → Viewer → Beta: detector control. Meant for first tests and demos, not as a replacement for a beamline control system.

Every setting and command has a ? that says what it does and names its SIMPLON key, the name to use when you later script it.

Network and privacy

ALBIS has no telemetry and no analytics. Your images, file paths and the datasets you browse are read from disk and sent to your own browser — they are never uploaded anywhere, and the interface loads no fonts or scripts from the internet.

One exception: at startup ALBIS asks GitHub whether a newer release exists, so it can tell you when to update. That request carries the version you are running and nothing else. Uncheck Settings → Connection → Check for updates on startup and ALBIS makes no outbound request of its own accord at all. An offline machine is fully functional; the check simply fails quietly.

Live sources are the only other traffic, and they go only to the SIMPLON or JUNGFRAUJOCH address you entered.

Troubleshooting

  • If the viewer shows OFFLINE, wait for the backend to start or restart the launcher.
  • If no image appears, check the selected dataset and threshold in the Data tab.
  • If overlays look stale during playback, pause and switch the overlay tool off and on once.
  • If a file will not open, ALBIS names the reason — a file still being written by the filewriter is the usual cause, and retrying once it is complete normally works.
  • If every request fails with 403 and a message about allowed hosts, you are reaching ALBIS under a name it does not answer to. This happens behind a reverse proxy: add the proxy's hostname to Settings → Connection → Allowed hosts.
  • If your settings appear to have reset, ALBIS could not read its configuration file and started on defaults rather than refusing to start. The log says which file and why; saving from the Settings dialog replaces it.
  • On first launch, Windows may show “Windows protected your PC” (choose More info → Run anyway). macOS builds are signed and notarized and should open normally.
  • If ALBIS asks you to reload, the server was upgraded or restarted on a different build while this tab stayed open, so this page is running older code than the server. Reloading clears it.
  • Use Help → View Backend Log for runtime diagnostics, and the Versions button in the bottom right to copy the exact build you are running into a bug report — a version number alone cannot tell two builds of the same release apart.
